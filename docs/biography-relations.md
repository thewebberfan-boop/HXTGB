# 履历动态关联与机构沿革

## 入口

- `src/lib/relationGroups.ts`：当前界面的分组及逐段计算。
- `src/lib/biographyRelations.ts`：时间区间和机构名称匹配基础函数。
- `src/lib/institutionIdentity.ts`：带来源和年代的历史名称解析。
- `src/components/BiographyRelationPanel.tsx`：关系分组、历史职级、双方证据并排查看。
- `src/components/InstitutionHistoryCard.tsx`：每个机构详情页的历史沿革卡片。

## 逐段归属（用户明确要求）

以左侧当前履历记录为唯一匹配目标。两人在证监局、交易所分别同期任职，分别在那两段右侧出现；不得把另一段履历的交集塞进当前段，也不展示跨生涯累计交汇徽章。同一段对同一人只显示一张卡，优先明确交集，其次可能交集，再次非同期记录；同组内取较长交集。双方原始经历可在卡片展开核对。

没有人物关系表。全量人物数据与机构沿革在每次渲染时计算；机构筛选不限制候选人物。

## 分组与日期边界

1. 明确重叠：按输入日期的最保守边界仍存在交集。缺起始月按当年12月、缺结束月按当年1月计算保证交集；不把这些计算边界当原始事实展示。
2. 可能重叠：外部区间相交，但保守区间不能确认；同月交接、同年入学毕业边界属于此组。
3. 同校不同时期：学校相同，已知学习时段不重叠。
4. 同校时间待核：学校相同，年份未知、异常或源于学制推算；不称同期同窗。
5. 同机构先后任职：有效任期不相交，单独折叠显示，不计入同期人数，不推断直接前后任接替。

“明确”指日期计算，不代表原始履历经过确证。未找到关联也不代表现实不存在。任职起点缺失、推导任期、明确历史但结束日期为空，不生成同期或先后关系。`endYear: null`仍沿用原模型“至今”的约定。

卡片单位、部门、职务及职级均使用匹配的历史记录；历史职级缺失显示待核，不使用当前职级补位。关系卡片移除当前年龄。教育卡片不显示当前职级。

## 来源绑定

任职与教育记录可填 `sourceIds: string[]`，指向该人物 `sources`。教育记录另支持可选 `id`。来源的 `supports` 若包含精确的履历ID也视为绑定；不对自然语言支持描述做模糊自动绑定。

展开后并排呈现双方经历与本段绑定来源；尚未绑定则明确提示。人物的其他来源单独折叠列出，不自动为本段背书。点击姓名仍可进入完整档案。审计检查不存在的 `sourceIds`。

## 机构历史沿革录入

在 `src/data/csrcData.ts` 对应 `Unit` 上维护可选 `history` 数组；沿革随项目数据保存，不是浏览器临时状态。每个机构页均显示卡片，空数组显示待补，不虚构历史。

每项字段：`id`、`name`（当时名称）、`startYear`、`endYear`（适用年份，未知留空）、`changeType`（established/rename/merge/split/other）、`continuity`（same_entity/related_entity/unverified）、`note`、`sources`（与人物来源相同结构）。

只有连续性为 `same_entity`、类型为设立或更名、有可定位来源链接、有效年份完整，才启用历史名身份匹配。记录整段年份必须在该名称适用范围内；边界不明或跨更名长段需先拆分/核实，不能强行归并。多个实体共用一个旧名时拒绝自动匹配。

合并、拆分仅展示关联历史，不自动视为同一主体。同系统、地区、母子机构不自动合并。原文名称不被替换。当前机构名称使用 `Unit.name`；若展示名称带描述性附注，应在数据整理时与实际机构名称核对，而非靠子串猜测。

学校沿革使用同一 `InstitutionIdentity` 结构，在 `src/data/schoolIdentities.ts` 维护。当前注册表留空，待有来源后录入；不预填猜测的并校等价关系。

本次交付是逻辑、结构与展示代码，不包含机构沿革史料普查，也未加入浏览器编辑器。以后新增沿革需核验来源、适用年代及连续性，修改数据后关系自动重新计算。
