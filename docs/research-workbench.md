# 本地研究工作台与版本化事实库

2026-09-27。此版本以本地文件和命令行工作台实现持久化、核验门槛、版本追踪和公开投影，不提供联网写入API或账号后台。网页不是研究底稿编辑器。系统检查证据记录的完整性，不能替代人或模型实际阅读原文。

## 数据分层与唯一入口

| 位置 | 用途 |
| --- | --- |
| `research-data/people/人物ID.json` | 持久研究库；候选、事实版本、证据版本、冲突双方、推理规则、发布事件 |
| `docs/research/people/人物ID.md` | 搜索日志、未结构化线索、身份消歧、查询断点；与JSON里的F/S/I编号对应 |
| `src/data/legacyData.ts` | 原大文件的完整兼容基线，保留已有覆盖顺序；不代表全库已核验 |
| `src/data/generatedResearch.ts` | 工作台生成的公开字段／撤下指令；不手工修改 |
| `src/data/csrcData.ts` | 页面及业务代码的稳定入口，合并基线和公开投影 |
| `src/types/research.ts` | 研究库类型；与页面的履历类型分开 |

研究JSON不被网页导入，也不放在`public`目录。研究库不等于私密保险箱：只保存公开职业信息和必要短摘要，不放凭证、私人信息、付费全文。代码仓库若日后被分享，研究文件也可能被分享。兼容基线仍随应用分发；本机制防止**新增研究候选与冲突底稿**被带入页面，不是清除已经在旧库发布过的信息。

## 记录与版本

- 每个人物文件含`schemaVersion: 1`、`personId`及`evidence`、`facts`、`rules`、`publications`四个数组。人物必须已经在基线注册；新增人物壳、机构名册和照片仍按既有手册独立审核。
- S事实来源、F字段事实、I推理规则各自使用稳定ID和从1递增的`revision`。修订必须在数组末尾追加，旧版本不改写、不删除。
- 一项F只管理一个目标：`basic`基础字段，或`career`/`education`下某个稳定`recordId`的字段。目标不可换绑；同一字段的不同说法用同一F的后续版本和`alternatives`保存。
- JSON的F是字段断言，不是独立岗位数。按`recordId`归组统计岗位／教育经历，不能把字段数报成履历增量。
- 来源保留`originGroup`以识别同源转载；权威性不等于证明力。`reading: read`只表示已读，事实还必须有明确定位、支持范围、身份依据和反向复核。
- `candidate / supported_direct / supported_observation / derived / conflicted / rejected`是本研究库的真实状态枚举，不直接写入`CareerRecord`。
- 冲突版本至少保存两个`alternatives`，各带值、证据引用与说明。解决后追加新事实版本，旧冲突和原结论仍可追溯。不同日期性质不应误合为一个冲突。

## 日常使用

```bash
npm run research:report
npm run research:import -- /绝对路径/人物草稿.json
npm run research:import -- /绝对路径/人物草稿.json --write --expect <本次预览返回的previewToken>
npm run research:check
npm run test:research
npm run audit:data
npm run build
```

导入文件是**完整的人物JSON**：复制现有文件到草稿，保留四个数组的已有前缀，再追加新版本。新人物研究文件可以从空数组开始，但其人物ID须已注册。第一次导入返回字段前后对照、整段撤下警告、双向关系变化、下游推理状态和`previewToken`；审阅后显式`--write --expect <previewToken>`才落盘。草稿、研究数据或代码变化都会令旧确认码失效。模型应使用文件编辑工具制作草稿，不能通过旧生成脚本重建整库。

写入使用独占写锁、预写事务日志及逐文件原子替换。日志在任何业务文件写入前保存完整前后快照，覆盖人物研究JSON、公开投影、版本文件、兼容基线和学校身份表。中断后保留pending事务；此时正常导入、导出、构建和启动检查均被阻止，必须先按[安全与恢复说明](research-safety.md)恢复。若文件已被外部同步改成既非旧值也非新值，停止恢复并保留现场。不要绕开工作台直接修改正式历史。

`npm run dev`启动前及`npm run build`流程会导出；构建在锁内进行，成功且输入版本未变才封存版本。`npm start`会检查数据、生成文件、成功构建及BUILD_ID一致性，过期构建拒绝启动。页面显示内嵌版本，打开、重新聚焦和每60秒（页面可见时）核对只读版本接口；过期或无法核对时明确警告，不自动发布或替换业务数据。运行中的开发服务需在代码或数据修改后重新导出并确认热更新，生产预览需重新构建并重启。**推理失效仍在导出／构建时处理，页面版本轮询不是自动研究。**已有已接管字段不能从库中直接消失；撤下请追加事件而非删人物文件。

## 逐字段公开门槛

一条直接事实的核心结构如下，内容只是模板，不能用占位符冒充已复核：

```json
{
  "id": "F002",
  "revision": 1,
  "target": { "kind": "career", "recordId": "稳定履历ID", "field": "position" },
  "value": "原文明说的职位",
  "status": "supported_direct",
  "citations": [{ "id": "S001", "revision": 1, "locator": "实际章节或页码", "statement": "仅概括原文明确支持的字段" }],
  "review": { "at": "2026-09-27", "by": "实际核验者", "identity": "同一人的对应依据", "countercheck": "实际做过的反向核验" },
  "note": "研究说明，不自动公开"
}
```

对应S版本结构为：`{ id, revision, source: InformationSource, reading, originGroup, note }`。`source`保留标题、发布者、真实链接、类型、访问日期、supports；实际原文读取状态未知时用`unread`，受阻用`blocked`。引用必须精确指向存在的S版本，只有最新版本仍为已读且可定位，直接事实才可公开。

通过门槛不等于自动发布。首次接管字段须追加：

```json
{ "id": "P001", "factId": "F002", "action": "publish", "at": "2026-09-27", "reason": "实际发布依据" }
```

这建立持续绑定：之后F的最新修订若仍符合门槛，投影采用新值；变成冲突／候选／否决／失效则撤下。主动撤下追加`action: withdraw`事件，恢复须追加新的publish事件。新发布事件若不符合核验门槛，导入拒绝。

`basic`当前支持出生年月、籍贯、性别、个人职级；任职和教育字段白名单见`RESEARCH_FIELDS`。新经历可分字段积累，但任职至少有机构对应（外部机构可空ID）、名称和职位，观察点还要日期。缺必要字段或组合无效时不展示该段，并给出复核提示。已有无稳定ID的教育经历先补稳定ID，再建立绑定。

任职观察字段必须落到`recordKind: observation`的记录，不能把一次活动中的职位更新到连续任期上。非计算字段（如职级）撤下不应抹去仍有效的日期关联；日期和机构依据失效则停止使用相应关系。学校本身来自推导时不生成确定校友匹配。

撤下值不会恢复基线旧值；出生年丢失会去掉依赖的出生月，任期年份丢失会去掉月日。学校被撤下仍可保留其他可靠教育信息，但不再计算校友关系。受影响的旧长摘要不继续展示；若接管的是旧现职记录，顶部“当前在任”摘要转待核，不能仅凭过去截至日证明今天仍在职。

## 推理、依赖及失效

`derived`事实必须有复核记录及`inference`：规则ID/版本、跨人物输入F的ID/版本和`rationale`。规则版本保存`description`、`assumptions`、`invalidWhen`、`allowedWording`及`enabled`。`allowedWording`是允许公开的边界说明，不能写内部草稿。

系统检查完整依赖图：输入修改（即使值没变）、输入证据版本变化／撤回、冲突、否决、规则更新／停用均使下游推理递归失效。缺失引用不能导入；循环引用不具备公开资格。重新复核须追加新事实版本，引用新输入版本；不会自动把旧推理“修好”。

规则是受约束的研究判断登记，不是任意脚本执行器；系统不会替研究者证明假设成立。机构身份和同名消歧等所有关键前提也应录成输入事实；未登记的外部变化不能被依赖图自动发现。页面原有同机构／同校算法仍随公开履历和机构沿革重新计算，不声明相识或私人关系。

## 验证边界

运行研究测试、记录测试、关系测试、审计、类型检查与构建。测试中的虚构人物属性只在临时目录和内存，不落入正式数据。初始研究库仅迁入郭淑华2003年观察点的一条旧库线索，状态为candidate，没有已读证据或发布事件；135份公开档案与迁移前完全一致。

当前已具备本地连续研究闭环。多人联网编辑、认证权限、数据库事务、图形化录入界面和全量旧数据事实核验不属于本版；兼容基线保留原样，后续逐人迁移而不是批量宣布已核验。
