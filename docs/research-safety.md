# 研究发布保障与故障恢复

## 1. 先预览，再写入

执行`npm run research:import -- /绝对路径/草稿.json`只预检，不写业务数据。返回：

- `preview.fieldChanges`：实际公开对象的字段路径、旧值、新值（null表示无值）；包含连带变化，不只列草稿字段。
- `preview.removedRecords`：哪些整段任职／教育经历将暂不显示及原因。字段看似小改动也可能触发整段撤下。
- `preview.relationChanges`：新增、消失和变更的关联；同时列目标人物和其他人物一侧的影响。同一关联的两个方向分列，不把行数当作独立关系数。
- `preview.inferenceChanges`：跨人物下游推理的资格和失效原因变化；没有公开的推理也会报告。
- `previewToken`：本次输入和草稿的校验摘要，不是账号凭证或授权令牌。

检查后运行`npm run research:import -- /绝对路径/草稿.json --write --expect <previewToken>`。确认码不匹配时重新预览，不能绕过检查。原文核验、录入和发布权限仍按用户任务；技术确认码不能替代授权。

## 2. 版本链与启动检查

版本摘要覆盖人物研究文件、应用源代码、工作台脚本及构建配置，生成到`src/data/generatedResearchVersion.ts`。不包含研究内容的明文；客户端不会拿到研究JSON。

`npm run build`依次导出、取得写锁、构建、复查输入摘要，成功后在`.next/research-release.json`保存摘要及BUILD_ID。构建失败、中途输入变化、缺少成功标记、数据变化后只重新导出而未构建，均不能通过`npm start`的前置检查。不要绕过npm脚本直接调用`next start`或`next build`。

页面顶部显示本页版本；只读`/api/research-version`只返回有限状态及版本摘要，不返回路径、候选、冲突内容或故障堆栈。页面加载、窗口重新聚焦／恢复可见和可见时每60秒核对。接口不可用不显示“已同步”；客户端旧页面与新服务版本不同也显示过期。

这是版本警告和启动门槛，不是实时推送或自动部署：已有浏览器在下一次核对前可能短暂显示旧状态；警告不会自动清空页面或改动数据。版本一致也不代表人物事实已核验。此实现面向当前完整本地项目，裁剪源码的独立部署包须另行设计版本清单，不应直接套用。

## 3. 每次写入的自动备份

事务日志存放在`research-data/.transactions/<事务ID>.json`，包含前后完整快照、校验摘要、时间、操作类型和状态。人物JSON、公开投影、版本文件、兼容基线、学校身份表均在快照内。先落日志，再写文件，最后标记committed；不自动清理历史备份。

```bash
npm run research:backup
npm run research:recovery
npm run research:restore-backup -- <备份或事务ID>
```

手工备份不改变业务数据。`restore-backup`将指定事务的**写入前**快照恢复到新的`research-data/.recovery-copies/restore-*`目录，输出实际路径，不覆盖现库。核对后按需要追加更正版本；不要用历史快照整体覆盖现库，抹掉后来追加的研究历史。

备份目录被Git忽略，但仍在同一项目／同步盘内；它保护误写和中断，不是独立设备的灾难备份。用户应将重要快照另行纳入已有异地备份方案。备份包含研究材料，不能因为它被Git忽略就认为它已加密或私密。

## 4. 中断事务恢复

1. 运行`npm run research:recovery`定位pending事务。
2. 先预览：`npm run research:recover -- <事务ID> resume`或`rollback`。
3. 核对文件清单后，加`--write`实际执行。`resume`完成此次写入，`rollback`回到此次写入前。rollback可能移除该未完成事务新建的文件，但完整前后备份仍保留。
4. 恢复后运行`research:export`、`research:check`、`audit:data`及测试，再构建和启动。完成或回滚的旧事务不能再次直接恢复到现库。

恢复仅允许文件当前内容等于该事务旧值或新值。出现第三种内容、额外人物文件、损坏日志、非法路径或符号链接时拒绝覆盖，先保留同步冲突双方并人工核对。事务处理是本地可恢复的多文件写入协议，不是分布式数据库事务；不要在多台OneDrive客户端同时写这个目录。

## 5. 写锁处理

`research-data/.write-lock/owner.json`记录进程、主机、时间和随机标识。普通操作从不抢锁。若进程已崩溃，可显式运行`npm run research:unlock`；只有确认同一主机、进程已不存在才回收。活动进程、其他主机或无法辨认的锁一律拒绝。释放锁不等于恢复事务，随后仍需检查pending日志。

## 6. 验证范围

`npm run test:safety`覆盖预览影响、确认码失效、三个写入边界的故障注入、继续／回滚、同步冲突、日志损坏、符号链接拒绝、备份提取、锁保护、过期构建拒启和页面版本状态。测试全部使用隔离临时目录，不通过篡改真实人物事实演示故障。文件系统刷盘和校验提高可恢复性，但不承诺抵抗硬件损坏、恶意本地篡改或云盘的所有冲突行为。
