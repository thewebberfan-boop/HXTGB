# HXTGB 持续研究与模型交接说明

版本：1.0，2026-09-27。适用于后续模型或人工持续搜集、核验、推理和补充公开职业履历。

目标：持续增加有依据的独立事实，同时保留尚待验证的有价值线索。发现范围与公开标准分别管理：搜索可以广泛，事实表述必须与证据的实际证明范围一致。已证实职位而任期不明时保留职位，不为填满时间轴猜日期。

本文规定连续工作流程；[研究手册](../biography-research-handbook.md)规定网站入口、查询包和正文阅读方法；[关系说明](../biography-relations.md)规定现有关系计算的行为。字段是否受支持以当前类型和实际消费者代码为准。研究状态、版本及推理依赖现由[本地研究工作台](../research-workbench.md)承载，查询日志和详细论证仍保存于底稿。

## 1. 每次接手的执行顺序

1. 阅读当前用户任务，确认已授权范围：机构、人物、研究截止日，以及是否包含正式数据修改。沿用仍有效的授权，不重复询问已明确的事项。仅要求研究或制定方案时，不自行发布网站或改动正式档案。
2. 查看仓库状态，保留已有未提交工作。若默认 Git 无法运行，可使用系统 `/usr/bin/git`；不要操作 Git 锁文件来绕过错误。
3. 完整阅读本文及研究手册，再读 [续接索引](progress.md)、当前批次和相关人物底稿。涉及关系推理时阅读关系说明；入库前阅读当前类型、数据覆盖层及相关展示代码。
4. 区分历史交接声明和本轮实际核验。缺少原文定位或逐人底稿的旧完成记录保留为历史记录，不据此宣称自己已读原文。
5. 从批次的“下一项具体动作”继续。已读材料在事实未变时复用；现任状态更新、矛盾出现、正文变动或证据缺失时定向复查，并说明重查原因。
6. 范围明确时默认每批约 5 人。先完成已有高价值待办和错误纠正，再推进新人物；保留难查人物队列，避免长期只做资料丰富者。
7. 若范围尚未指定，可盘点现有底稿和缺口；历史批次的下一步不自动代表本次用户已选择该范围。

| 文件 | 职责 |
| --- | --- |
| `docs/research/progress.md` | 当前任务入口、活跃批次、断点、下一动作；不复制全部事实 |
| `docs/research/batches/YYYY-MM-DD-主题.md` | 截止日、名册口径、人物队列、覆盖、增量和交接 |
| `docs/research/people/人物ID.md` | 唯一的人物研究底稿，跨批次持续追加查询、来源、事实、冲突与推理 |

| `docs/research/templates/batch.md` | 新批次模板 |
| `research-data/people/人物ID.json` | 版本化研究库，按工作台规则追加证据、事实、冲突和推理 |

沿用人物 ID；人物内查询 `Q001`、来源 `S001`、事实 `F001`、推理 `I001` 逐次递增。跨人物引用写 `人物ID/F001`。底稿 ID 与应用内 `sourceIds`、履历 ID 分别记录映射，不能假定它们自动对应。

每读完一篇相关正文，及时登记来源和候选事实；每处理完一个人物，保存判断和下一查询；本轮结束时更新批次与续接索引。不要等到整批结束才落盘。中断恢复时先查最后写入状态，按 ID 去重，避免重复增加来源或经历。

## 3. 四阶段工作循环

阶段代表工作职责，同一个模型可顺序完成。独立复核有助于发现遗漏，但多个模型的一致回答不构成多个独立来源；只有当用户或适用指令授权时才进行多代理委派。

### A. 高召回发现：建立候选池

- 执行研究手册查询包，覆盖现任机构、每个已知历史机构、媒体、教育及适用的年报、论坛、披露材料。
- 优先恢复旧模型已经提出但未收录的岗位、学校和时间线索。逐条导入人物底稿，标注“旧模型输出，待核验”及可追溯位置；没有原始输出就记为未取得，不凭记忆重建。
- 候选可以没有完整日期或原始链接。模型记忆、搜索摘要、百科和聚合页用于提出检索方向，不能据此确定事实或编造来源链接。
- 不因候选含一处错误而否定其他字段；也不因其中一项被证实而接受整段简历。
- 先读高价值原文，再沿新机构、部门、旧名和年份扩展；每条新线索记录明确的下一查询，不重复泛搜姓名。
- 将候选保存与公开数据写入分开。搜索输出再多，也不会自动提高正式档案核验等级。

### B. 逐项验证：确认来源实际支持什么

将材料转换为最小可核对的陈述，分别核对身份、机构、部门、职位、学习经历和日期属性。同一经历的属性可以逐项核验，但统计时仍只算一段经历。

每项记录四个维度，不把它们平均为“准确概率”：

| 维度 | 记录内容 |
| --- | --- |
| 身份对应 | 依据哪些机构、时间或其他公开职业线索确认是同一人；尚有何疑点 |
| 来源属性 | 原发布者、实际读取载体、来源类型、同源转载组、访问日 |
| 证明范围 | 原文明说的事实、仅能确认的观察点、不能证明的字段 |
| 日期性质与精度 | 任命、生效、活动、报道或观察日期；日／月／年／未知分别保留 |

清楚直接的官方材料一条可以足够；可核对的可靠媒体正文也可支撑其明确陈述。不要求每个职位都取得任免令，不机械要求两条来源。复杂同名、含糊表述和冲突需要追加核验。转载可用时注明实际载体与原发布者，不能把同源转载计算为相互独立的证据。

事实状态沿用手册：`candidate`、`supported_direct`、`supported_observation`、`derived`、`conflicted`、`rejected`。来源阅读状态（如 `blocked`、`wrong_person`、`duplicate`）另记在来源台账，不能与事实状态混用。

### C. 反向复核与受约束推理

先检查可能推翻结论的材料：同名异人、职位兼任、党委与行政职务差异、报告年份、提名与实际任命、学校到访与学习经历的区别。每个新增公开事实至少复查来源对应和日期口径；出生、学历、精确任期、个人级别、处分状态、照片及存在冲突的事实重点复核。

推理分两种用途：

1. **提出搜索假设**：可以用候选线索提出“可能曾在某部门工作”等检索问题，必须保留为待证假设。只能驱动下一查询，不能进入公开结论或事实统计。
2. **形成可展示结论**：输入必须是已核验且与结论相关的事实。保存输入事实 ID、规则、假设、反例检查、允许表述及失效条件。涉及尚未解决的关键冲突时只保留为研究问题。

| 输入（以下均为示意） | 允许的处理 | 不成立的扩展 |
| --- | --- | --- |
| 2019年活动正文称甲为副总经理 | 记为2019年该活动时已任副总经理，这是直接的时间点观察 | 将2019年或活动月份填作上任日期 |
| 2019年为副总经理，2021年为总经理 | 先保留两个观察点；仅在替代关系、无兼任及时间口径有证据支持时，提出有条件的变化区间 | 自动写出连续任期、唯一晋升过程或精确交接月份 |
| 两人在同一机构的可靠任期重叠 | 按已知日期精度计算任职交集，保留边界不确定性 | 推断相识、直属上下级、私人关系或政治派系 |
| 同校学习经历、部分日期未知 | 保留校友关联及是否同期待核；已知年份交集仍不证明同班 | 以常规学制倒推出确定入学年或声称同学 |
| 只有2016年、2018年两次同职活动记录 | 保留两个任职观察点 | 默认中间两年持续在任 |

推理登记为 `Ixxx`。如公开结论还登记为事实 `Fxxx`，其状态必须是 `derived`，并引用对应 `Ixxx`。不能把推理结果重新当作独立直接证据，避免循环论证。输入被纠正、撤销或机构身份发生变化时，标记所有依赖推理待复核，并在授权的数据更新中同步修正相关公开表述。

现有界面关系算法会使用库中履历计算，库中并非所有记录均已事实核验。算法的“明确重叠”仅描述日期计算；不能据此宣称证据已验证。研究流程的事实门槛与当前应用实现应分别报告，不声称本文件已改造算法。

### D. 入库与逐项对账

1. 对每项候选给出可追踪去向：已入库、已证实待入库、证据不足、存在冲突、已否决。等待入库必须说明原因和目标字段。
2. 已确认职位但起止不明，可按[研究数据语义](../research-data-model.md)保存为历史任职并省略未知日期，显示于人物页和泳道的未定位经历区；观察点单独保存。将事实 ID 与应用履历、来源 ID 对应记录在底稿。
3. 不将历史结束时间未知写成 `endYear: null`；它仅兼容旧“至今”。新现任记录必须记录证据截至日。学校与学位现在可分别未知，只知道学位时保存已知部分，不填虚构院校。
4. 修改前搜索人物全部出现位置，检查`legacyData.ts`兼容基线及人物研究JSON。新增量通过工作台预检及导入，核对公开投影和运行时最终对象。不要运行旧生成脚本重建整库，不直接改写历史版本。
5. 保留稳定 ID、已有已核验字段和其他人的工作。来源绑定到具体履历或字段；肖像独立保留出处。局部核验使用 `partially_verified`。
6. 推导若能被现有字段与界面准确标注，可以在授权范围内展示；如会被渲染成确定任期或现任状态，暂留研究底稿，登记表达能力缺口。
7. 类型、日期模型、界面和算法改造应有明确实现范围；本文不自动启动这些开发任务。

## 4. 连续工作、阻塞与停止条件

默认在用户已指定的范围内持续推进队列，无须每完成一人重新确认。页面受阻时按手册作有限重试并走原稿、附件、合法转载等替代路线；某人物受阻时推进其他可做项，将受阻项保留在队列。

优先顺序：公开数据的已发现错误与身份混淆 → 已读高价值候选核验及入库 → 名册缺口与旧模型遗漏线索 → 职业时间空白与教育缺口 → 日期细化与补充来源。按具体任务调整并记录原因。

“本轮研究完成”必须满足手册第9节的路线覆盖、候选处置和停止条件。连续两轮扩展没有新增有效事实只表明本轮趋于饱和，不等于穷尽互联网。因预算、上下文或工具限制结束时写“暂停”及未完成路线；必要事实尚未核实写“待核”，不用“未公开”替代“尚未查到”。

每次结束前保存四项：最后处理的 Q/S/F/I 编号；已写入与待写入事实；阻塞与替代尝试；下一项可直接执行的搜索式或原文链接。具体动作不可只写“继续研究”。

本文是跨轮工作协议，不创建后台任务、定时器或无人值守自动执行；用户下次要求继续时按断点恢复。历史交接和本文均不单独授予提交、推送或对外发布权限。

## 5. 验证与交付

- 只改文档：检查链接、模板字段与规则是否一致，无须执行整站构建。
- 修改人物数据：按手册运行数据审计和类型检查；涉及任期、机构名称或关系来源时运行关系测试；在端口4000的页面核对受影响档案、来源和时间轴。
- 修改应用代码：按影响补做关系测试、构建与页面验证。区分“结构通过”“事实核验通过”“页面通过”。
- 命令必须记录实际结果。遇到长时间停滞先检查当前任务状态，不叠加启动同一构建；未完成不能写通过。不能凭单条缓存错误断言根因。
- 审阅最终差异，确认新增、纠正、保留和删除的依据。用户未请求部署时不自动部署。

每批同时报告：新增独立岗位／教育经历，属性补准，撤销错误，候选处置，待入库事实，来源覆盖和未解决缺口。日期观察、正式任期和推理数量分别列出。分母不明不报覆盖百分比，链接总数不等于新增事实数。

首次执行本流程，可在用户指定范围内选约5名资料条件不同的人做试点，并建立人工或原文复核过的参考事实清单。比较“参考事实找回数／清单内事实数”与抽检错误率，单独跟踪旧模型线索找回情况；参考清单不完整时该指标不代表全网召回率。根据漏查原因改查询路线，不通过降低证据门槛提高产量。
