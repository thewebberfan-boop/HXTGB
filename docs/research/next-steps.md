# 下一步计划

更新日期：2026-09-27。当前已完成研究语义、版本化工作台、发布影响预览、版本一致性及备份恢复。下一阶段优先用真实小批研究验证闭环，再按实际瓶颈扩展系统；本计划不自动授权联网研究、数据发布或新增外部服务。

## 1. 确定研究范围并完成小批试点（优先）

- 请用户确定人物／机构范围、研究截止日，以及是否提供旧模型原始输出。未取得旧输出时，不将整个兼容基线当作该模型的结果。
- 建议先选择3—5人，包含已知日期不完整、观察点或来源冲突的案例。郭淑华`F001@1`可作为候选起点，具体原文入口见[续接索引](progress.md)，不因列入计划就视为已核验。
- 按[持续工作说明](continuous-work.md)完成广泛发现、逐字段核验、反向复核、受约束推理、导入预览、授权范围内发布和页面对账。
- 验收：每项候选均有去向（已证实、待核、冲突或否定），已证实信息不因日期不完整而遗漏；公开字段有具体证据，推理保留输入和失效条件；批次及人物底稿留下可恢复断点。

## 2. 以试点结果衡量覆盖与可信度

- 在批次底稿记录候选总量、逐项核验结果、已证实待入库项、已入库项及未解决缺口，不只比较页面数据条数。
- 对用户提供的旧模型输出逐项对账，说明正确信息是否保留、为何暂不能发布；未提供对照集时，不宣称测得整体召回率。
- 先通过文档与现有`research:report`完成评估；只有重复性统计成为实际瓶颈时，再获授权增加覆盖看板或统计脚本。旧库审计数字应重新运行取得，不能把历史统计当作实时结果。

## 3. 将验证流程固化为自动检查（后续工程）

- 经授权后增加持续集成：记录语义、关系、研究库、安全测试，以及数据审计、生成投影一致性和生产构建。
- 先检查已提交投影是否过期，再构建，避免构建时自动重新生成掩盖漏提交。全新检出应能通过验证，不依赖本地备份、临时文件或未跟踪资源。
- 验收：故意引入过期投影、非法研究记录或失败测试时检查失败；成功构建保持版本一致。持续集成不自动推送业务数据或部署。

## 4. 补足运行保障，按需扩展

- 重要研究积累前，由用户选择独立于当前OneDrive目录的备份目的地、保留期和访问权限，再配置异地备份并演练提取。当前本地事务快照不等于异地灾备。
- 保持单写入者。多人／多设备并发、远程部署、账号权限或图形编辑器均需另行设计与授权，不把本地锁当作分布式锁。
- 系统新增功能优先处理试点暴露的真实阻塞；暂不以大规模迁移或自动生成事实替代逐项核验。
